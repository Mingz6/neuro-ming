## Architecture: The Two-Tier Voice Loop

```
User Voice
    │
    ▼
Speech-to-Text (Deepgram)
    │
    ▼
Fast Conversational Loop (Claude Haiku)
    │   ├── Simple reply → Text-to-Speech (ElevenLabs) → Voice Out
    │
    └── Needs heavy lifting?
            │
            ▼
        Tool call → Spawn Opus Worker Agent
                        │
                        ▼
                    Work done (email check, calendar, etc.)
                        │
                        ▼
                    Write result → Shared Bus
                        │
                        ▼
                Haiku reads bus → TTS announcement back to user
```

**Key properties:**
- Haiku loop is always-on, always fast — voice latency is low for casual chat
- Opus workers can run in parallel (10+ at once), each posting to the shared bus
- Haiku doesn't block waiting — it can announce when ready ("I've queued that, will let you know")
- Agent framework: **[unclear in transcript — "PykeCat sub-agents" — possibly PocketFlow or Pydantic AI]**

## Key Insights for Neuro-Ming

### 1. The Haiku → Opus pattern is the right M3 architecture
Current Neuro-Ming is one model, one turn, synchronous. The next big leap is:
- Keep a fast conversational shell (cheap model or even just GPT-4o-mini)
- Spawn async workers for actual tasks (email, calendar, file ops, code)
- Return results via a shared bus that the voice shell can announce

### 2. Deepgram > Azure STT (worth evaluating)
Current M2 uses Azure OpenAI TTS (output). For STT (input), when we add it, Deepgram is the recommendation — "most stable, best value for money."

### 3. ElevenLabs > Azure OpenAI TTS (worth evaluating)
The person considers ElevenLabs the best-in-class for TTS. Azure `tts` (nova voice) works fine but ElevenLabs has better voices and more stable API. Worth swapping in M3.

### 4. Queue + announce UX pattern
When a user asks for something async, the voice assistant should:
- Immediately acknowledge ("Queuing that for you")
- Continue being available for other requests
- Proactively announce when the worker finishes

This is way better UX than blocking on a 10-minute email check.

### 5. Parallel workers on shared bus = core power
Ability to say "check my email, check my calendar, and check the weather" and get all three in parallel, with the TTS shell announcing each as they come in.
